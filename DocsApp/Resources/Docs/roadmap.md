# 当前限制与路线图

本文如实列出当前版本（0.5，本地原生原型）的能力边界，以及分阶段建设计划。诚实划定边界是这个项目的核心原则之一。

## 当前限制

### 平台与分发

| 限制 | 说明 |
| --- | --- |
| 仅 macOS 验证 | macOS 14+；iOS / iPadOS 是后续目标，`HidanCore` 无 AppKit 依赖可移植，但导入、相机权限、后台音频、屏幕方向与文件访问需另做适配 |
| 非公证发行 | 本地 ad-hoc 签名原型，不是 App Store／公证版本 |
| 无崩溃恢复 | 强制结束或崩溃不保证录像完成；运行中的练习不跨启动恢复 |
| 无跨设备同步 | 没有历史迁移与冲突处理；CloudKit 只在明确需要后加入 |

### AI 与识别

| 限制 | 说明 |
| --- | --- |
| 无自动舞步分类 | 未训练舞步识别器；100 个基础动作名来自 AIST 官方元数据，是来源标签而非识别结果 |
| 无舞蹈评分 | 骨架置信度不能变成「动作完成度 92%」；评分需要教师量表与独立用户测试 |
| 无三维重建 | 视频捕捉生成二维观测模型，不从用户视频估计 3D 姿态，不伪造深度 |
| 无生成式编舞 | 不自由生成三维编舞、不生成过渡动画、不重新生成舞步 |
| 精度未实拍验证 | 真实舞者、全身动作、快速转身和地板动作的检测精度仍需专项实拍评估 |

### 音乐与节拍

| 限制 | 说明 |
| --- | --- |
| 无第一拍检测 | BPM 估计只给整体速度，不找第一拍、不跟随中途变速 |
| 无精准音画同步 | 视频播放器和音频播放器没有承诺共同时间基下的精准同步；A–B 循环可能有 seek 边界延迟 |
| 无 MusicKit | 受开发者协议 3.3.6(D) 约束，Apple Music 曲目不能随意解码、变速或配视频 |
| 内存开销 | 全帧报告保存在内存，长视频支持需要顺序文件存储与中断恢复 |

### 「一起跳」

- 只做同一网络（或 VPN 内网）直连：无 NAT 穿透、无中继服务器
- 一次只连一位好友：无多人房间
- 无语音通话、不传导入音乐、不同步 3D 示范

### 内容

- 未包含授权教学视频；16 张文字卡待教师审核
- 文字卡与 AIST 片段尚未逐条对应
- 没有删除已导入副本的界面，重复导入产生并列副本
- 四个舞种各有基础卡片与入门/进阶入口，但不代表完整课程已覆盖
- AIST++ `ignored` 低质量序列不得直接用于教师级评分

## 分阶段路线图

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| **0：原型（已完成）** | 原生训练台、16 动作卡、规则组合、音乐/视频工具、姿态导出、记录与调研 | 编译、核心行为测试、程序包启动与实际 UI 检查；无虚构能力 |
| **0.2：AIST++ 接入（已完成）** | 全量 3D 标注与 100 基础动作名；动作库、收藏、逐帧/片段跟练与计划接入 | 数据无损校验完成；UI 和训练行为按验证记录单独验收 |
| **1：内容与数据** | 教师校对动作、授权多视角示范、个人动作档案、歌曲首拍标注 | 授权逐项明确；初学者能独立完成看/练/回看；真实视频观测质量审计 |
| **2：有限动作识别** | 3–5 类时序模型、负例、拒识、动作分段 | 跨舞者测试、每类 precision/recall、混淆矩阵、拒识率、域差异报告；模型不能判断时明确拒识 |
| **3：可解释反馈** | 有教师量表的时序/顺序/局部运动指标 | 教师一致性与独立用户测试；错误反馈可追查到观测与模型版本 |
| **4：个性化与生成** | 熟练度/疲劳驱动训练、检索式组合、可选生成模型 | 先验证规则生成的用户价值，再证明生成模型带来改进；动作可做性需人工复核 |

## 后续路线上的具体项

- 第一拍对齐、双视频同步回看
- 舞步识别（建议先选 3–5 个边界明确的站立任务，按舞者和拍摄 session 划分训练/验证/测试，避免同一视频切片泄漏）
- 从用户视频估计 3D 姿态（macOS 14 / iOS 17 起可研究，需深度来源、尺度与接触误差验证）
- 质量评分（DTW 可对齐不同速度序列，但会把节拍错误对齐掉，不能将对齐距离直接当节奏评分）
- iOS / iPadOS 移植
- 长视频的顺序文件存储与中断恢复
- 训练负荷输入：「今日可用时间、疲劳、酸痛／不适、昨日负荷、想练什么」四类输入 + 透明规则负荷调整

## 资源投入判断

> 后续投入最有价值的资源是**少量授权、标注一致的真实示范与练习视频，以及一位能审核街舞动作与反馈的教师**，而不是立即汇集数十万段来源不明的视频。

本轮没有安装第三方模型、调用付费 AI、建立云服务或下载课程——这些并非运行原型所需。

## 数据模型的长期方向

长期模型按观测、含义和教学评价分层：

```text
MoveDefinition ──< ReferenceTake ──< PoseSequence ──< PoseFrame
       │                  │                 │
       ├── Prerequisite   └── RightsRecord   └── ObservationQuality
       ├── TeachingCue
       └──< ActionSegment >── ModelVersion

TrainingPlan ──< TrainingBlock ──> MoveDefinition
TrainingSession ──< SessionEvent / UserReflection
MusicAsset ──< BeatAnnotation       AssessmentRubric（后续）
```

业务元数据可采用 SwiftData 或 SQLite + FTS5；逐帧姿态与媒体放外部文件，数据库记录路径/hash/索引，避免把长视频每个关节点做成可观察 UI 对象。详见项目 `docs/PRODUCT_AND_TECHNICAL_PLAN.md`。
