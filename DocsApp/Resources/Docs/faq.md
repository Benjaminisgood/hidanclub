# FAQ 与故障排查

## 构建与启动

### `swift build` 或运行失败怎么办？

确认环境：**macOS 14+** 与 **Swift 6 工具链**（源码为 Swift 5 语言模式）。项目无第三方依赖，不需要网络下载包。推荐直接用 `./script/build_and_run.sh`，它会编译、打包 `dist/HidanClub.app`、ad-hoc 签名并启动。

### 应用打不开 / 提示签名问题？

当前是**本地 ad-hoc 签名原型**，不是 App Store／公证发行版本。用 `./script/build_and_run.sh` 构建启动，或验证签名：

```bash
codesign --verify --deep --strict dist/HidanClub.app
```

### `swift test` 报 `no such module 'XCTest'`？

本机 Command Line Tools 缺少 XCTest 时的已知现象。用 `./script/test.sh` 代替——它运行可复现行为探针（15,108 项检查），仅在这一具体缺依赖时启用独立验证，其他错误仍会失败。测试文件完整保留，具备 XCTest 的环境会同时运行 `swift test`。

## AIST++ 数据

### 动作库看不到 3D 示范 / 提示缺数据？

需要先安装 AIST++ 数据（约 876 MB 下载）：

```bash
python3 script/aist_dataset.py
```

需要 Python 3.10+、NumPy 2.x、curl。数据存于 `~/Library/Application Support/HidanClub/Datasets/AISTPlusPlus/`。安装后运行 `./script/test_aist.sh` 验证。

### 下载中断了怎么办？

直接重跑 `python3 script/aist_dataset.py`。下载用 `.partial` 文件支持续传；脚本先检查磁盘空间；官方 SHA-256 和字节数匹配后才原子发布。中断的首次安装不会伪装成完成（`manifest.json` 最后发布）。

### 怀疑数据损坏？

运行独立复核：

```bash
python3 script/aist_dataset.py --verify-only
```

不下载、不写文件，从原始 ZIP 独立重算并核对 manifest 和所有二进制数据。不同内容的文件拒绝覆盖，不会静默替换。

### 想把数据放到外置硬盘？

```bash
python3 script/aist_dataset.py --root '/Volumes/Research/AISTPlusPlus'
```

### 官网说 10,108,015，为什么应用显示 1,123,873 帧？

两者都正确但含义不同：10,108,015 是**多机位图像统计**（每个序列最多九台相机视角）；1,123,873 是**独立三维时间帧**（1,408 个 `cAll` 序列的 N 累加）。九个视角不是九段独立 3D 动作。项目没有删帧来凑网页数字。

### 视频和音乐在哪里下载？

不在本应用范围内。原 AIST 视频、图像和音乐来自 AIST Dance Video Database，适用其独立 Terms of Use，**不在 `keypoints3d.zip` 里**；适配脚本不下载这些媒体，CC BY 4.0 只覆盖 Google 的标注。

## 摄像头与录像

### 摄像头没反应？

首次点击启用时 macOS 才请求相机权限。检查系统设置 → 隐私与安全性 → 摄像头。权限拒绝、迟到授权、无设备和重复启停都有明确处理路径。离开训练台、系统睡眠和退出应用会关闭相机。

### 录像为什么没有声音？

**设计如此**：录像保存当前相机尺寸的原画面，不录制麦克风、不叠加示范或骨架。

### 录像没进视频库？

正常退出会等待录像完成和入库。强制结束或崩溃不保证录像完成——录像恢复只接收配有有效完成标记的 MOV，未完成文件不会自动入库，原件保留在 `PendingRecordings/`。

### 界面显示丢帧计数？

这是如实报告：输入缓冲区不主动丢帧，但如果设备跟不上、系统丢弃输入，界面显示系统丢帧数。不能声称所有机器永不丢帧。

## 音乐与 BPM

### 导入音乐后 BPM 是空的？

两种常见原因：音频**短于约 8 秒**，或**没有稳定周期**。此时保留失败原因，需要手动填写 BPM，应用不会在每次启动时重试。估计只分析开头最多 4 分钟，不找第一拍、不跟随中途变速。

### 估计的 BPM 差了一倍？

已知现象（倍频误差）。用 ½× / 2× 倍速纠正，或手动改成听到的 BPM。置信度只表示周期有多稳，不表示一定正确。

### 为什么动作没有卡在音乐第一拍上？

BPM 估计**不提供第一拍相位**，只对齐速度。八拍区间是基于所选起始帧与源速度的练习辅助，不等同于自动识别原音乐节拍。第一拍对齐在路线图上。

### 导入的音乐能传给「一起跳」的好友吗？

不能。导入的音乐不传给对方——对方听到**同速的原创节拍**。协议只共享播放、暂停与速度状态。

## 「一起跳」

### 搜不到对方的房间？

「一起跳」只做**同一网络（或 VPN 内网）直连**：确认两台 Mac 在同一 Wi‑Fi／网段；检查 macOS 的本地网络权限；也可以手输 `IP:端口`（支持 `host:port`、`[ipv6]:port`、`name.local:port`）加入。没有 NAT 穿透和中继服务器，跨公网不可用。

### 能三个人一起跳吗？

不能，一次只连**一位**好友。没有多人房间、语音通话或 3D 示范同步。

### 对方能看到我的画面吗？

默认**不共享**。共享选项有三档：不共享 / 只共享骨架 / 画面与骨架，必须由用户显式打开。链路用房间码派生的 TLS-PSK 加密，对方画面只在内存解码显示，不保存、不录音。

## 视频与识别

### 识别一个长视频要多久？

全帧报告保存在内存，长视频／高分辨率会增加时间与内存开销；本版未对长度做静默裁切。播放器逐帧推进，设备延迟时播放变慢而不跳帧。

### 为什么这一段没有骨架？

无人帧、多人帧和低置信度帧**全部保留**但如实显示：无检测保留空观测，多人保留 ambiguous 标记。没有检测到可用人体的片段不会被当作可用示范，应用不伪造骨架。

### 覆盖率 60% 是不是动作质量 60 分？

不是。**覆盖率只表示检测状况，不是动作质量**。应用不提供舞蹈评分。

### 导入 JSON 被拒绝了？

导入按文件名给出具体原因。常见拒绝：schema 版本不是 1、片段越界、重复次数越界、没有可用骨架、缺时间戳、缺 confidence、PTS 不一致。坐标与 PTS 从不改写，不一致即按帧号拒绝。派生元数据（帧数统计、duration、PTS 重建）有宽容路径，每次修正写入导入提示。

### 重复导入同一个文件会怎样？

提示已有副本数量并仍存新副本（产生并列副本）。目前没有删除已导入副本的界面。

## 训练与历史

### 暂停的时间算进训练时长吗？

不算。只有实际运行时长计入；跳段不把剩余时间或被跳过段计为完成；历史含计划内休息，不标成纯运动时长或能量消耗。

### 崩溃后训练记录还在吗？

正常退出会保存当前练习；强制结束或崩溃不保证。崩溃恢复、历史迁移与跨设备同步尚未实现。

## 内容与教学

### 文字卡能当正式课程用吗？

不能。16 张原创文字卡用于产品导航，**未经教师审核**，不冒充完整传统动作定义。基础版本排除倒立、power moves、强迫关节幅度与高冲击组合；Breaking 参考可浏览不代表适合直接跟练。

### 应用会给我的动作打分吗？

不会。质量评分需要教师量表、标注一致性和误导反馈评估，暂不提供。实时反馈（入镜、关节可见性、肘膝角度）是检测与观察提示，不是舞蹈评分或医疗判断。
