# 实时摄像头跟练

训练台内嵌实时摄像头捕捉：本机 Apple Vision 二维关节检测、入镜指导、可见关节与肘膝投影角度，配合四种显示方式与示范同屏对照。**所有分析在本机进行，画面不上传。**

## 启用摄像头

- 摄像头入口默认可见，**首次点击启用时**才请求 macOS 相机权限（`NSCameraUsageDescription` 已写入 Info.plist）
- 使用设备的当前格式；没有人为设置较低相机 FPS、抽帧或缩小输入
- 每个收到的相机缓冲区按顺序交给 Apple Vision，**图像和检测关节来自同一帧**一起显示
- 默认只预览；点击「开始录像」后才录制

权限相关的拒绝路径经过验证：注入拒绝授权、迟到授权取消、无设备和重复启停均被正确处理。

## 实时反馈

| 反馈项 | 说明 |
| --- | --- |
| 身体是否入镜 | 入镜指导提示，帮助调整站位 |
| 是否多人 | 多人时**不自动挑选某人**，只如实提示 |
| 当前关节可见性 | 逐个关节的可见状态 |
| 二维肘膝投影角度 | 按视频宽高比还原后计算；置信度不足时显示空缺，不给假数值 |

> **定位声明**：这些是检测与观察提示，**不是舞蹈评分或医疗判断**。转身、快速运动、遮挡、地板动作和远近变化都会影响单摄像头二维检测。

## 镜像与数据保真

相机画面和关节一起镜像显示，方便「照镜子」式跟练；**数据本身不因镜像被改写**。导出的模型保留原始坐标系。

## 帧处理与丢帧

- 输入缓冲区不主动丢帧或定时抽帧
- 串行分析和同步发布使处理队列有界
- 如果设备跟不上、系统丢弃输入，界面显示**丢帧计数**——不能声称没有硬件丢帧
- 相机逐帧状态独立发布，导航与训练计划不订阅每帧图像变化（避免整份界面每帧重建）

一次真实 UI 观察记录：捕获／分析均为 1,563 帧、错误与系统丢帧均为 0。这是当次观察，不代表长期性能或真实舞蹈准确度验证。

## 录像

1. 点击「**开始录像**」开始录制
2. 点击「**停止并保存**」，录像自动放进视频库，不上传

录像合同：

- 保存**当前相机尺寸的原画面**，不含示范、骨架、镜像预览或 UI
- **不录制麦克风**，没有音轨
- 录像原件位于 `PendingRecordings/`，视频库原字节复制入库
- 切页、关闭相机和正常退出会先等待文件完成，再停止采集；退出也等待入库任务
- 失败时保留现有原件并显示错误
- 录像恢复只接收配有有效完成标记的 MOV，未完成文件不会自动入库

生命周期探针覆盖：注入式开始／立即停止、重复启停、中断、写入失败、录像收尾先于退出回调、完成标记与隔离目录检查。

## 摄像头关闭时机

离开训练台、系统睡眠和退出应用会**关闭相机并清除当前画面**。始终提供可见的相机停用入口。未录制或另存用户相机画面。

## 与训练台联动

实时捕捉与[训练台](training-studio)的四种画面布局配合使用：并排、只看示范、只看摄像头、叠加。叠加模式在相机画面上显示半透明示范模型，可调大小与透明度。

## 验证边界

合成探针（8/8 合成 VFR 缓冲完整处理、PTS 和原始图像尺寸、图像与姿态同帧发布、合成系统丢帧计数、停止后回调抑制）**没有开启系统相机**，也不构成真实硬件录制或舞蹈质量验证。真实舞者、全身动作、快速转身和地板动作的检测精度仍需专项实拍评估。

```bash
./script/test_live_pose.sh         # 实时姿态探针
./script/test_camera_recording.sh  # 录像生命周期探针
```
