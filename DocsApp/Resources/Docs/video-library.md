# 视频库与录像

视频库保存导入的原视频和训练台录像，是「视频 → 肢体识别 → 动作库」流程的起点。侧栏入口名为「**视频库**」。

## 导入视频

- 通过系统文件面板**多选导入**舞蹈视频
- 视频**原字节保存**到本机 `Videos/Originals/`，条目与模型使用 UUID 命名和**原子写入**
- 重启后继续回放；原路径移走后仍可播放（因为库内是完整副本）
- 损坏文件保留、不被静默覆盖；指向库外的符号链接被拒绝

QA 覆盖：原片字节一致、重启恢复、竖屏方向、并发导入、录像重试去重、完整 VFR 帧及 PTS、模型关联、取消隔离。

## 训练台录像自动入库

训练台点击「开始录像」→「停止并保存」后，录像自动放进视频库。录像为当前相机尺寸的原画面，**不录音、不叠加示范或骨架**。原件先在 `PendingRecordings/`，入库时原字节复制。详见[实时摄像头跟练](live-camera)。

## 肢体识别

点击「**开始肢体识别**」逐帧提取关节：

- 使用 **Apple Vision** 的身体关节模型（`VNDetectHumanBodyPoseRequest`），全帧 2D 人体关键点分析
- **原始 PTS 保留**：每个解码帧的 timestamp value/timescale 逐位保留
- 无人帧、多人帧和低置信度帧**全部保留**：无检测保留空观测，多人保留 `ambiguous` 标记，不在不同人间静默跳转
- 方向校正：8 种标准旋转／镜像的方向映射经过验证，非标准变换被拒绝
- 取消不发布部分报告；旧任务不能覆盖新任务；无效源返回明确错误

识别完成后得到一份完整二维动作模型（PoseReport），可保存、复查与导出 JSON。

## 骨架逐帧复查

- 逐帧切换查看骨架叠加与原视频，核对捕捉结果
- 无人帧明确显示「无人」，**不伪造骨架**
- 时间显示 PTS 与秒数（例如第 2 帧显示 `0.033333 s` 和 `20/600` PTS）
- 覆盖率（coverage）只表示检测状况，**不是动作质量**

## 原视频播放工具

用于核对捕捉结果的播放能力全部保留：

| 能力 | 说明 |
| --- | --- |
| 原视频播放 | 系统 `AVPlayerView`（`NSViewRepresentable` 窄包装） |
| 镜像 | 水平翻转对照练习 |
| 慢放 | 0.5× 等速度，暂停时精确 seek |
| A–B 循环 | 学习用途；可能有 seek 边界延迟，不能用于专业 sample-accurate 编排导出 |

播放器依原始相邻 PTS 持续时间推进，每次回调仅推进一帧；设备延迟时播放会变慢，**不能通过跳帧追赶**。

## 从视频库到动作库

完整流程（详见[动作分段与编排](segmentation)）：

1. 「视频库」多选导入舞蹈视频，或在训练台录像
2. 点击「开始肢体识别」逐帧提取关节
3. 检查二维动作模型、检测覆盖情况和原视频
4. 使用智能分段或手动设定连续 A–B、调整顺序和重复次数
5. 「导入动作库」保存当前 A–B 为独立动作，进入训练台慢放、镜像、循环跟练

没有检测到可用人体的片段不会被当作可用示范。

## JSON 导出

成功完整分析后可按用户选择导出 JSON：完整模型导出（`*.hidanclub.json`）包含全部帧、关节、置信度与原始 PTS，可被动作库「导入 JSON…」原样读回。导出 JSON 明确 `frameIndexBase: 0`，可 round-trip。

## 存储与性能边界

- 全帧报告保存在内存，长视频／高分辨率视频会增加时间与内存开销；本版未对长度做静默裁切
- 界面只降低刷新频率，不改变数据点
- 正式长视频支持需要顺序文件存储与中断恢复（路线图）

```bash
./script/qa_video_library.sh        # 视频库字节一致性与恢复
./script/test_camera_recording.sh   # 录像生命周期
./script/qa_captured_motion.sh      # 完整模型：VFR 解码、Double 位精度、2 万帧并发保存
```
