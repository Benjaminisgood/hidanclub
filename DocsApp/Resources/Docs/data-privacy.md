# 数据与隐私

Hidan Club 没有账户、没有服务器、没有云端同步。本文说明每类数据存在哪里、如何隔离测试、以及应用在隐私上的具体承诺。

## 数据都存在哪里

所有用户数据位于 `~/Library/Application Support/HidanClub/`：

| 目录 / 文件 | 内容 |
| --- | --- |
| `Videos/` | 原视频（`Videos/Originals/` 原字节副本）和视频条目 |
| `CapturedMotions/` | 完整二维识别模型 |
| `VideoMotionLibrary/` | 导入动作库／编排库的独立副本（含从 JSON 文件导入的副本） |
| `Music/` | 导入音乐的原字节（`Music/Originals/`）、估计节拍和手动 BPM |
| `PendingRecordings/` | 训练台录像原件（入库前） |
| `Datasets/AISTPlusPlus/` | AIST++ 完整 3D 数据（约 1.8 GB，含源 ZIP） |
| `history.json` | 训练历史 |

## 测试隔离变量

QA 脚本用环境变量把数据目录指到临时位置，**不触碰用户真实库**：

| 变量 | 隔离目标 |
| --- | --- |
| `HIDAN_VIDEO_DIR` | 视频库目录 |
| `HIDAN_CAPTURE_DIR` | 捕捉模型目录 |
| `HIDAN_PUBLISHED_DIR` | 已发布动作／编排目录 |
| `HIDAN_MUSIC_DIR` | 音乐库目录 |
| `HIDAN_DATA_DIR` | 训练历史（`history.json`） |

## 隐私承诺

### 不上传

- 所有肢体识别、节拍估计、分段分析在**本机**进行
- 摄像头画面不上传、不云端处理
- 录像自动进本机视频库，「不上传」是入库合同的一部分

### 不录音、不录屏对方

- 训练台录像**不录制麦克风**
- 「一起跳」不写任何媒体文件：对方的画面只在内存里解码显示，不保存、不录音

### 网络行为清单

| 场景 | 网络行为 |
| --- | --- |
| 日常使用 | 无——应用运行不需要网络 |
| 「一起跳」 | 局域网 Bonjour 广播 + 两台设备直连（TLS-PSK 加密），无服务器 |
| AIST++ 安装 | 一次性从官方 GitHub release 下载（Python 脚本，与应用运行时无关） |

### 系统权限

| 权限 | 时机 | 说明 |
| --- | --- | --- |
| 相机（`NSCameraUsageDescription`） | 首次点击启用摄像头 | 默认只预览；离开训练台／睡眠／退出关闭相机并清除画面 |
| 本地网络（`NSLocalNetworkUsageDescription`、`NSBonjourServices`） | 首次搜索或开「一起跳」房间 | 仅局域网设备发现 |

### UserDefaults 存了什么

「一起跳」用 `UserDefaults` 记住：本机显示名、随机生成的对端 ID、画质选择。人形样式选择用 AppStorage 保存。没有广告标识、没有分析 SDK。

## 数据完整性设计

- **原子写入**：条目与模型使用 UUID 命名和原子写入，manifest 最后发布
- **损坏保护**：损坏记录不静默覆盖——损坏 JSON 原始字节在读取、训练结束和重试后保持一致，自动保存被阻断
- **拒绝越界**：指向库外的符号链接不接受；不同内容的重新安装拒绝覆盖
- **副本独立**：导入动作库保存独立副本（新 UUID、记录来源 id），编辑不修改识别原件
- **退出安全**：正常退出会等待录像完成和入库，再保存当前练习；强制结束或崩溃不保证录像完成

## 原始数据保真

- 完整原始帧和时间戳保留：原始 PTS（value/timescale）逐位保真
- AIST++ 两层坐标以 Float64 保留，维持精确 60 FPS、全部帧、源帧顺序和缺失值（NaN 原位保留）
- 镜像等显示变换不改写数据本身
- 导出 JSON 可 round-trip：重新导入逐位相等

## 尚未实现

- 崩溃／强制终止恢复
- 历史版本迁移
- 跨设备冲突处理（无同步，也就无冲突处理）
- CloudKit 只在明确需要跨设备同步后加入，并另做媒体容量和冲突设计
