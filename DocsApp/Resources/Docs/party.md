# 「一起跳」P2P 连线

「一起跳」让两台 Mac 上的好友**点对点直连对练**：一台开房间，另一台加入，输入房间码配对后互传画面与骨架，共享同一节拍。不经过任何服务器，不保存、不录音。

## 连接流程

### 房主（开房间）

1. 进入「一起跳」页面，点击开房间
2. 应用通过 **Bonjour** 在点对点 Wi‑Fi 上广播服务（服务类型 `_hidanclub._tcp`）
3. 生成 **4 位房间码**，等待客人加入
4. 客人输入房间码后，房主**确认**即完成配对

### 客人（加入）

1. 从**附近列表**选择房间，或手输 `IP:端口`（支持 `host:port`、`[ipv6]:port`、`name.local:port`）
2. 输入对方给出的 4 位房间码
3. 房主确认后配对成功

> 首次搜索或开房间时 macOS 会请求**本地网络权限**（`NSLocalNetworkUsageDescription`、`NSBonjourServices` 已写入 Info.plist）。

## 加密：TLS-PSK

链路使用**房间码派生的 TLS 1.2 预共享密钥（Pre-Shared Key）**加密：

- 双方由同一房间码独立派生密钥，密钥不经网络传输
- 基于 Network.framework 的 TLS 参数完成握手
- 回环 QA 验证了 TLS-PSK 握手、H.264 往返与节拍同步全链路

## 画面与骨架共享

画面按 **VideoToolbox H.264**（640 或 960 宽）直接发给对方，与**同一帧的关节**一起显示。

| 共享选项 | 内容 |
| --- | --- |
| 不共享（**默认**） | 只同步节拍，不传画面与骨架 |
| 只共享骨架 | 传关节数据，不传相机画面 |
| 画面与骨架 | H.264 视频 + 同帧关节 |

对方的画面**只在内存里解码显示**，不写任何媒体文件、不保存、不录音。画质选择记在 `UserDefaults`。

## 节拍同步

底部音乐条就是共享节拍：

- **房主的播放、暂停与速度镜像给客人**
- 「**一起开始**」用 **NTP 式时钟对齐**（ping/pong 采样估计时钟偏移），让两边同一瞬间倒数起拍
- 客人在**下一个八拍**进入（八拍网格 `beatsPerBar = 8`，条边界落在 `anchor + k × barLength` 的同一时钟上）
- **导入的音乐不传给对方**：房主播放导入曲目时，客人听到的是**同速的原创节拍**（协议里明确标记「房主在听客人没有的导入曲目」）

## 显示名与身份

`UserDefaults` 记住本机的显示名、随机生成的对端 ID 和画质选择。不注册账户，不联系通讯录。

## 限制（务必了解）

| 限制 | 说明 |
| --- | --- |
| 同一网络 | 只做同一网络（或 VPN 内网）的直连 |
| 无 NAT 穿透 | 跨公网不可用，没有中继服务器 |
| 单人房间 | 一次只连**一位**好友 |
| 无语音通话 | 不传音频、不录音 |
| 无 3D 同步 | 不同步 3D 示范，只共享节拍与可选画面/骨架 |
| macOS 优先 | 当前验证平台为 Mac |

## 隐私小结

- 不经过服务器：发现用 Bonjour 局域网广播，传输是两台设备直连
- 不写盘：对方画面只在内存解码显示，无任何媒体文件落盘
- 默认最小共享：出厂即「不共享」，画面/骨架共享必须由用户显式打开
