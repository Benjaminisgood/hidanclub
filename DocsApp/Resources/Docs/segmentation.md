# 动作分段与编排

从视频识别出的二维动作模型，经过**分段**变成可跟练的动作片段，再进入**编排库**组合成套练习。整个流程坚持一条原则：AI 只做观测与建议，人显式确认后才生效。

## 智能分段

本机 Vision 识别二维关节后，可依据**全帧动作变化**生成分段建议：

1. 设定目标片段秒数
2. 系统依据关节运动变化寻找边界，生成建议
3. **先查看建议，再显式应用**——不会自动改写任何东西
4. 应用后可调整 A–B 边界、片段顺序和重复次数
5. 「导入动作库」保存为独立动作

### 保守行为合同

| 情况 | 行为 |
| --- | --- |
| 缺少可靠骨架 | 拒绝生成建议 |
| 没有足够分界证据（短片／静止） | 保留整段，并说明原因 |
| 低可靠性 | 拒绝 |
| VFR／重复 PTS | 正确处理 |
| 旧异步结果 | 抑制，不覆盖新任务 |
| 旧版 JSON | 兼容 |
| 改名 | 不重置播放 |

> **明确边界**：没有重新生成舞步或过渡动画，不按音乐重分段，不做舞步命名。分段是基于 Vision 全帧结果的运动变化分析，**不是生成式舞蹈模型**。

QA 验证覆盖动作停顿附近的分段建议、完整连续覆盖与显式应用建议、手动边界。原生 UI 实测：智能生成 3 段，应用后改名并直接导入「我的动作」；导入编排库后将首段设为重复 2 次，保存后显示 31.24 秒，进入训练台名称／顺序／重复次数一致；退出重开后动作副本和编辑后的编排均保留。

## 动作库中的片段

「导入动作库」保存当前 A–B 为独立动作：

- 保留**完整原始帧**，使用独立身份，不修改视频识别原件
- 动作 A–B 与整套编排保存独立快照
- 编辑不会删除原始帧

## 编排库

编排库保存多片段的练习编排，包含两类内容：

### AIST 三维编排

编排库只排动作库里的**三维片段**：从 3D 示范的连续 A–B 片段加入，保留来源、坐标层、速度、顺序与重复片段。草稿按 UUID 持久化，支持排序、重复片段、不限四段；原始引用与哈希保留，损坏保护。

### 视频动作编排

「导入编排 JSON…」后出现「视频动作编排」列表，卡片含缩略图、片段明细、来源说明与「**练习这套**」按钮。编排保留全部片段顺序与重复次数。

### 练习这套

进入训练台按顺序分段训练：**热身 60 秒 → 每段循环 60 秒 → 段间休息 20 秒 → 放松 30 秒**。多参考编排训练验证覆盖完整 A–B／层／速度／顺序、230 秒两段预算、运行与暂停保护、库刷新不覆盖编排。

> 分段编排不等同于已自动对拍的连续 32 拍表演；侧栏和页面统一称为「编排库」，不再以 32 拍限制编排长度。

## 存储与完整性

- 独立副本保存在 `VideoMotionLibrary/`（含从 JSON 文件导入的副本）
- 来源身份、原始帧／时间戳保留；重启后恢复；编辑保存
- 损坏覆盖拒绝；8 个排队发布请求期间等待状态不提前归零
- 正常退出等待已提交的动作／编排发布及模型保存／导出
