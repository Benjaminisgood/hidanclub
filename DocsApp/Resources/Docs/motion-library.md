# 动作库

动作库是 Hidan Club 的统一入口，包含三个分类：**3D 示范**、**基本功**、**我的动作**。文字卡与 AIST 片段尚未逐条对应；编排库只排动作库里的三维片段。

## 3D 示范（AIST++）

「3D 示范」用于观察和片段跟练，数据来自本机安装的 AIST++ 完整 3D 标注：**1,408 条序列、1,123,873 个独立时间帧、10 个舞种**，精确 60 FPS，每帧 COCO 17 关节 × 3 坐标。

### 目录与检索

- 全量目录可见序列数与总帧数统计
- 支持**动作名／舞种检索**：例如搜索 `Running Man` 返回 12 条结果
- 100 个官方基础动作名由 AIST 官方元数据（`choreo.xlsx` 映射）提供，保留原文与出处——它们**不是**本应用 AI 的识别结果
- 支持**收藏**序列；舞种标签来自文件命名规范（`gBR` = Break 等），不是应用新训练的动作分类结果

### 播放与观察

| 能力 | 说明 |
| --- | --- |
| 逐帧查看 | 拖动时间轴逐帧观察，UI 帧数从 1 开始，导出 JSON 为 `frameIndexBase: 0` |
| A–B 区间 | 任意连续区间循环播放，起止段选择不改写原序列 |
| 八拍区间 | 基于所选起始帧与源速度的练习辅助，不等同于自动识别原音乐节拍 |
| 坐标层切换 | 原始 `keypoints3d` 与官方优化 `keypoints3d_optim` 两层，切换保持当前帧和 A–B |
| 连续片段导出 | 导出所选区间的每一个源帧，字节与来源连续切片完全相等 |

播放按源帧顺序推进，延迟回调不跳过数据帧；这不保证硬件显示了每次 UI 更新，也不宣称与音频精确同步。

### 三种人形样式

| 样式 | 外观 |
| --- | --- |
| 柔光人形（默认） | 连续胸腰／骨盆曲面、头颈、渐变粗细四肢、手掌与鞋形脚端，浅色摄影棚与柔光 |
| 霓虹人形 | 同一立体人体，紫青色材质和深色舞台 |
| 经典骨架 | 17 个 COCO 节点、19 条连接、左右双色与参考网格 |

人形样式可叠加原骨架、显示关节名称和参考网格。人体表面是风格化外观，直接由当前帧关键点驱动；体型、手掌、鞋形脚端不代表测量得到的额外关节或真实舞者外貌。缺少支持点的部位隐藏，不通过插值补帧。舞台圆盘、灯光与地面只是显示参考，不会将源数据重新贴地。

### 加入训练计划

选定 A–B 片段可直接加入训练计划，保留序列 ID、连续源帧范围、坐标层与播放速度。不能将舞种标签、BPM 或一次收藏当成能力评估。

## 基本功（16 张文字卡）

「基本功」提供 16 张原创文字练习卡，从 Hip-Hop、Popping、Locking、House 展开，覆盖四组八拍动作规则组合。

> **诚实声明**：文字卡用于产品导航，不冒充完整传统动作定义或经教练审核的课程，尚待教师审核命名、文化语境、示范和常见错误。

规则组合会检查输入、站立低冲击条件，并给出 BPM／先修／风格警示。基础版本排除倒立、power moves、强迫关节幅度与高冲击组合。

## 我的动作（视频导入的二维片段）

「我的动作」保存从视频中导入的二维动作片段：完整原始帧、置信度与原始 PTS 全部保留，使用独立身份（新 UUID），不修改视频识别原件。之后可进入训练台慢放、镜像、循环跟练。详见[视频库与录像](video-library)和[动作分段与编排](segmentation)。

## JSON 文件导入

动作库页右上角的「**导入 JSON…**」读取本机文件，可多选。接受两类文件：

1. 应用导出的**完整二维动作模型**（`*.hidanclub.json`，与「导出 JSON」写出的字节相同）
2. 只含**识别报告**的 JSON

日期可以是应用的参考日期数字或 ISO 8601 字符串；键顺序、缩进和多余字段不影响读取。

### 导入合同

导入只读取原文件，保存的是独立副本：新 UUID、记录来源 id、完整原始帧、置信度与原始 PTS 全部保留。动作库使用文件自带的片段范围（多段时取整体跨度）成为一条动作。

**宽容只作用于派生或描述性元数据**：

| 情况 | 处理 |
| --- | --- |
| `decodedFrameCount` / `detectedFrameCount` / `coverage` 缺失或自相矛盾 | 按保留帧重算 |
| `duration` 缺失 | 按末帧时间戳与相邻间隔推得 |
| 整数 PTS 缺失 | 由 timestamp 以 1e7 时基重建 |
| 每次修正 | 写进导入提示与副本的 `arrangementMethod` |

**坐标、置信度、帧顺序与原始 PTS 从不修改**：两者不一致时拒绝导入并指出第几帧。

### 拒绝规则

以下情况按文件名给出原因，且**不写入任何库文件**：

- schema 版本不是 1
- 片段范围越界
- 重复次数越界
- 没有可用骨架、无帧、缺时间戳、缺 confidence
- 垃圾文件、空文件、无关 JSON

重复导入同一文件会提示已有副本数量并仍存新副本（没有删除已导入副本的界面）。混合批次只发布有效文件；源文件 SHA-256 前后一致。真实导出 `center-dancer.hidanclub.json`（750 帧、601 检测、597 可用、片段 0–629、21.00 秒）已通过逐位相等校验。
