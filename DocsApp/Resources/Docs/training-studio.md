# 训练台与训练计划

训练台把训练示范、自己的摄像头画面和视频捕捉结果放进同一条跟练流程。训练台只显示当前练习内容、画面布局和跟练控制；内容选择在训练台之外完成。

## 进入训练台的方式

| 来源 | 携带内容 |
| --- | --- |
| 动作库 → 3D 示范单片段 | 序列 ID、完整连续帧范围、坐标层、播放速度 |
| 动作库 → 风格训练计划 | 四个训练风格各 3 个真实命名 AIST++ 动作 |
| 编排库 → AIST 编排 | 来源、坐标层、速度、顺序与重复片段 |
| 编排库 → 「练习这套」 | 视频动作编排按顺序分段训练 |
| 无示范 | 摄像头自由练习 |

缺少示范不能启动训练（自由练习除外）。AIST 编排从动作库的连续 A–B 片段加入；「练习这套」的节奏是：**热身 60 秒、每段循环 60 秒、段间休息 20 秒、放松 30 秒**——它不等同于已自动对拍的连续 32 拍表演。

## 训练计划生成

应用可生成 **10–45 分钟**计划（UI 提供 10 / 15 / 20 / 30 / 45）：

- 约 **1/6 热身**、约 **1/10 放松**并设置上限，其余分为基础动作与短休息
- 较长计划末尾加入熟悉动作自由连接
- 先修动作顺序有效，10–45 分钟方案精确合计
- 数字是可调整的产品规则，**未作为个体化运动处方验证**

时间分配和先修次序可查看 `HidanCore` 的 `PlanBuilder`。每个练习段有自己的示范模型；热身和休息显示下一动作预告，画面标明预告或回看，不把舞蹈示范冒充热身指导。

## 训练状态机

```text
idle → running ↔ paused → completed / stopped
```

| 规则 | 行为 |
| --- | --- |
| 暂停 | 时间不计入流程时长，恢复后接着计时 |
| 跳段 | 不把剩余时间或被跳过段计为完成；迟到的 tick 跨段补算，超出终点的时间不计入 |
| session ID | 稳定，完成记录去重；只在已开始且已结束时提供历史 |
| 系统休眠 | 自动暂停 |
| 历史记录 | 保存真实流程时间（含计划内休息），不能标成纯运动时长或能量消耗 |

手动跳到编排末尾会标记为**含跳过片段**，不冒充完整播放。

## 开始／暂停／换段联动

开始、暂停、下一段和结束会联动示范播放。加载下段时暂停训练计时；加载成功后继续，出错则保持暂停。连续快速换段时，加载完成后恢复用户意图。动作库播放器与训练播放器独立——查看别的动作不会替换训练片段。

## 四种画面布局

1. **并排**：左侧当前动作模型，右侧摄像头实时画面
2. **只看示范**：训练与示范播放状态保留，只改变画面布局
3. **只看摄像头**：同上
4. **叠加**：摄像头背景上显示半透明动作模型，可调整大小、透明度和拖动位置；3D 示范会隐藏舞台表面、保留人物照明

> **叠加模式的边界**：这是手动视觉对照，未做相机标定、动作相位或人体尺度自动对齐。叠加模式未启用相机时不放置拖动层，避免挡住授权入口。菜单暂停仍保留相机观察；离开训练台／睡眠／退出关闭相机。

AIST++ 保留柔光人形、霓虹人形和经典骨架三种样式；视频捕捉使用真实二维坐标模型，**不伪造深度**。

## 速度控制

- **原创节拍**下：示范速度控件调整本段速度，下段使用该段计划速度
- **音乐模式**下：动作速度 =「曲目 BPM × 播放速度 × 倍数」，最快 2 倍、最慢 0.25 倍；到不了时训练台会说明
- **视频动作**没有记录 BPM，仍按原片时间播放

这只对齐速度，不对齐第一拍。详见[音乐库与 BPM](music-library)。

## 训练历史

普通 AIST 计划与自定义 AIST 片段使用原有训练历史：只有实际运行时长计入，跳过时间不算完成。历史写入本地带版本 JSON（`history.json`），原子替换；损坏文件保留并阻止覆盖。正常退出会等待录像完成和入库，再保存当前练习；强制结束或崩溃不保证录像完成，运行中的练习也不跨启动恢复。

> 视频编排的播放进度是编排播放进度，**目前不写入普通训练历史**。

## 合理训练建议

建议后续加入「今日可用时间、疲劳、酸痛／不适、昨日负荷、想练什么」四类输入，用透明规则先做负荷调整。用力感升高时允许减幅度、减速、延长休息；没有身体状况信息时不自动推高强度。用力感为用户主观记录，不由视频估算。

进入 Breaking／地板动作必须有专门教学、场地和能力筛选，且需要重新评估单目关键点适用性。
