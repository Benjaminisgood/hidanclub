# 音乐库与 BPM

左侧「音乐库」放两类东西：**多套原创八拍**（各自记住一个速度）与**导入后永久保存的本地音乐**。两种播放器样式不同。

## 原创八拍

- 由 **AVAudioEngine** 在本机合成的原创八拍节奏，可存多套
- 每一套用 BPM 滑杆调速，并**记住自己的 BPM**
- 有记录 BPM 的示范跟着节拍走
- 八拍视觉只对原创节拍取音频渲染时间

QA 覆盖：原创节拍、暂停时间线保留、恢复、BPM 修改继续播放、非法 BPM 归一化、stop 重置、44.1 kHz 单声道 / 48 kHz 立体声切换、多次文件循环和切回原创。

## 导入本地音乐

| 环节 | 行为 |
| --- | --- |
| 导入 | 原字节保存到 `Music/Originals/`，JSON 记录时长、采样率、估计节拍和手动 BPM |
| 重启 | 恢复上次曲目和 ¼×/½×/1×/2× 倍速选择 |
| 保护 | 损坏记录和指向库外的符号链接不覆盖、不接受 |

QA 用合成踢鼓加踩镲验证：120 BPM 与 86 BPM 估计（误差小于 2）、原字节一致、手动 BPM、重启选择、短文件、垃圾文件、损坏记录和符号链接。

## BPM 估计

音乐在**本机**估计一个整体 BPM，方法是读取音频的**频谱通量（spectral flux）**，给出一个整体 BPM 和周期置信度。

### 估计的能力边界（重要）

- **不找第一拍**——只对齐速度，不对齐相位
- **不跟随中途变速**——只给一个整体值
- 只分析**开头最多 4 分钟**
- 置信度只表示周期有多稳，**不表示一定正确**
- 短于约 **8 秒**或没有稳定周期时保留失败原因，需要手填 BPM，且不在每次启动时重试
- 可随时**手动改成听到的 BPM**

> 校准记录：用本机 Apple Loops 的鼓和打击乐循环校准过，完全偏离标注速度的只有 2 条，其余落在标注 BPM 或它的二倍上。倍频误差用 ½× / 2× 或手填 BPM 纠正。这些循环不随仓库分发，未写进自动测试。

## 动作跟随倍速

音乐模式下动作速度公式：

```text
动作速度 = 曲目 BPM × 播放速度 × 倍数    （倍数 ∈ ¼×, ½×, 1×, 2×）
最终限制在 0.25–2 倍；到不了时训练台会说明
```

实测例：「100 BPM × 0.75 × 2× = 150」。**视频动作没有记录 BPM，仍按原片时间播放**，不参与倍速跟随。

离屏渲染能读到「两拍一动 · 动作 60」和「一拍两动 · 动作 240」两种细分显示。分段选择和 BPM 输入框由系统控件绘制，离屏图里是占位色。

## 底部音乐条

训练台底部的音乐条集中控制播放、暂停与速度；它同时就是「一起跳」的共享节拍来源——房主的播放、暂停与速度镜像给客人。详见[「一起跳」P2P 连线](party)。

## 不做什么

- 没有 MusicKit / Apple Music 集成：开发者协议 3.3.6(D) 明确约束 MusicKit 内容的下载、上传、修改及与其他内容同步，不能把订阅曲目当作可随意解码、变速、配视频或训练模型的音源
- 视频播放器和音频播放器**没有承诺共同时间基下的精准同步**
- 非 DRM 只表示能解码，不代表有公开分发或训练权
