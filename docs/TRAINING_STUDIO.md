# 实时训练台与视频动作编排

0.3 将训练示范、自己的摄像头画面和视频捕捉结果放进同一条跟练流程。Mac 优先，macOS 14 以上。

## 训练台

内容选择放在训练台之外：动作库选择单个片段或风格训练计划，编排库选择一套真实片段编排，点击进入训练台后携带原来的模型。侧栏和页面已统一称为「编排库」，不再以 32 拍限制编排长度。训练台只显示当前练习内容、画面布局和跟练控制；也允许无示范的摄像头自由练习。

AIST 编排从动作库的连续 A–B 片段加入，保留来源、坐标层、速度、顺序与重复片段。编排库的「练习这套」按顺序进行分段训练：热身 60 秒、每段循环 60 秒、段间休息 20 秒、放松 30 秒。它不等同于已自动对拍的连续 32 拍表演。

- **并排**：左侧当前动作模型，右侧摄像头实时画面。
- **只看示范 / 只看摄像头**：训练与示范播放状态保留，只改变画面布局。
- **叠加**：摄像头背景上显示半透明动作模型，可调整大小、透明度和拖动位置。3D 示范会隐藏舞台表面、保留人物照明。该模式是手动视觉对照，未做相机标定、动作相位或人体尺度自动对齐。
- AIST++ 保留柔光人形、霓虹人形和经典骨架；视频捕捉使用真实二维坐标模型，不伪造深度。

普通 AIST 计划从官方基础动作名称中选取四个训练风格各 3 个示范。每个练习段都有自己的序列 ID、完整连续帧范围、坐标层和播放速度。原来的文字提示卡保留在动作库，不把它们强行配到不相同的舞蹈。

开始、暂停、下一段和结束会联动示范播放。热身、休息和放松仍有单独提示；画面标明预告或回看，不把舞蹈示范冒充热身指导。加载下段时暂停训练计时；加载成功后继续，出错则保持暂停。缺少示范不能启动训练。动作库播放器与训练播放器独立，查看别的动作不会替换训练片段。

普通计划与自定义 AIST 片段使用原有训练历史：只有实际运行时长计入，跳过时间不算完成。音乐独立于动作相位，尚未自动对拍。示范速度控件调整本段速度，下段使用该段计划速度。

## 摄像头捕捉

摄像头入口默认可见，首次点击启用时才请求 macOS 相机权限。使用设备的当前格式；每个收到的相机缓冲区按顺序交给 Apple Vision，图像和检测关节来自同一帧一起显示。默认只预览；点击「开始录像」后才录制，点击「停止并保存」后自动放进视频库，不上传。

录像保存当前相机尺寸的原画面，不含示范、骨架、镜像预览或麦克风音轨。切页、关闭相机和正常退出会先等待文件完成，再停止采集；退出也等待入库任务。录像原件位于 `PendingRecordings`，视频库原字节复制入库。失败时保留现有原件并显示错误。

反馈包括身体是否入镜、是否多人、当前关节可见性和二维肘膝角度。角度按视频宽高比还原后计算，置信度不足时显示空缺。多人时不自动挑选某人。相机画面和关节一起镜像；数据本身不因镜像被改写。

输入缓冲区不主动丢帧或定时抽帧。串行分析和同步发布使处理队列有界；如果设备跟不上、系统丢弃输入，界面显示丢帧计数，不能声称没有硬件丢帧。离开训练台、系统睡眠和退出应用会关闭相机并清除当前画面。

这些是检测与观察提示，不是舞蹈评分或医疗判断。转身、快速运动、遮挡、地板动作和远近变化会影响单摄像头二维检测。

## 视频库 → 肢体识别 → 动作库或编排库

1. 在「视频库」多选导入舞蹈视频，或在训练台录像。原视频保存到本机，重启仍可回看；点击「开始肢体识别」逐帧提取关节，所有原始 PTS、无人、多人和低置信度帧保留。
2. 检查二维动作模型、检测覆盖情况和原视频。覆盖率只表示检测状况，不是动作质量。
3. 使用智能分段：设定目标片段秒数，依据关节运动变化寻找边界，先查看建议，再显式应用。也可手动设定连续 A–B、调整片段顺序和重复次数。
4. 「导入动作库」保存当前 A–B 为独立动作；「导入编排库」保存整套片段顺序和重复次数。两者都保留完整原始帧，并使用独立身份，不修改视频识别原件。之后可进入训练台慢放、镜像、循环跟练。

## 从 JSON 文件导入动作库 / 编排库

动作库页右上角的「导入 JSON…」和编排库页的「导入编排 JSON…」读取本机文件，可多选。接受两类文件：应用导出的完整二维动作模型（`*.hidanclub.json`，与「导出 JSON」写出的字节相同），以及只含识别报告的 JSON。日期可以是应用的参考日期数字或 ISO 8601 字符串；键顺序、缩进和多余字段不影响读取。

导入只读取原文件，保存的是独立副本：新 UUID、记录来源 id、完整原始帧、置信度与原始 PTS 全部保留。动作库使用文件自带的片段范围（多段时取整体跨度）成为一条动作；编排库保留全部片段顺序与重复次数，并出现在编排库的「视频动作编排」列表，可直接「练习这套」进入训练台。

宽容只作用于派生或描述性元数据：缺失或自相矛盾的 `decodedFrameCount`/`detectedFrameCount`/`coverage` 按保留帧重算，缺失的 `duration` 按末帧时间戳与相邻间隔推得，缺失的整数 PTS 由 timestamp 以 1e7 时基重建；每次修正都会写进导入提示和副本的 `arrangementMethod`。坐标、置信度、帧顺序与原始 PTS 从不修改：两者不一致时拒绝导入并指出第几帧。版本不是 1、片段越界、重复次数越界、没有可用骨架、缺时间戳或垃圾文件都会按文件名给出原因，且不写入任何库文件。

保存的是完整二维观测及编排索引，编辑不会删除原始帧。视频原字节复制到 `Videos/Originals`，条目与模型使用 UUID 命名和原子写入；损坏文件保留，不被静默覆盖。保存成功的原视频、模型、导入副本在重启后可直接载入。没有检测到可用人体的片段不会被当作可用示范。

AI 识别使用 Apple Vision 的身体关节模型；分段是基于其全帧结果的运动变化分析，不是生成式舞蹈模型。缺少可靠骨架时拒绝生成建议；没有足够分界证据时保留整段，并说明原因。未做音乐自动对拍、舞步命名或新动作生成。

播放器依原始相邻 PTS 持续时间推进，每次回调仅推进一帧；设备延迟时播放会变慢，不能通过跳帧追赶。视频模型跟练的时间显示是编排播放进度，目前不写入普通训练历史。尚未自动识别舞步名称、按音乐分节、恢复三维骨骼或生成过渡动作。
