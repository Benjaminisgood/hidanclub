# 项目介绍

这份文档给两个时候看：第一次打开仓库，以及几个月后自己回来对代码。首页 [README](../README.md) 讲它是什么、现在能做什么、怎么跑起来。这里接过原来 README 里偏结构、数据和校验的部分，按 2026-10-04 的代码写。界面截图是 2026-09-24 在本机 Mac 上截的，文件在 `docs/images/`，没有再压缩。

版本以构建脚本写进包里的为准：`CFBundleShortVersionString` 0.5.0，`CFBundleVersion` 7，包标识 `club.hidan.mac`。

## 仓库里有什么

```text
Package.swift                 Swift 包。macOS 14，工具链 6.0，语言模式 Swift 5
Sources/HidanCore/            纯 Foundation。计划、节拍、AIST 模型、一起跳协议、练习钟
Sources/HidanClub/            SwiftUI 应用
  App/HidanClubApp.swift      入口、退出时等录像入库、设置窗口
  Views/                      侧栏九页和训练台
  Stores/                     各库的读写和内存状态
  Services/                   相机、Vision、录像、音乐、节拍估计、一起跳传输
  Models/                     视频条目、二维动作、JSON 导入
  Support/                    颜色、播放条、人形样式、标志
  Resources/                  标志、NOTICE、AIST 动作名和训练用的 12 个示范
Tests/HidanCoreTests/         能跑 XCTest 时的单元测试
script/                       构建、AIST 安装、不依赖 XCTest 的探针
docs/                         方案、数据合同、验证记录、本介绍
dist/                         构建产物，不进 Git
```

两个目标故意分开。`HidanCore` 不碰 AppKit、SwiftUI、相机和文件对话框，探针和单元测试都打在这里。`HidanClub` 负责窗口、权限和把东西写进 Application Support。

应用跑起来不下载模型，也没有第三方 Swift 包。AIST++ 的下载和校验才用 Python。

## 窗口怎么串起来

`ContentView` 是一个 `NavigationSplitView`。侧栏是 `ClubPage`：动作库、基本功、视频库、音乐库、编排库、一起跳、练习录、设置页、资源库。

点「开始练习」不会再切一页去选示范。`beginPractice` 记下来源（`TrainingSource`：`aist`、`generated`、`captured`，或者什么都不带），然后整块换成 `TrainingView`。返回时停掉示范、基本功动作、视频动作和 AIST 播放。全屏会先收起侧栏，再让窗口进入系统全屏；退出全屏时收回。

底部 `MusicBar` 一直在。练习进行中，播放按钮同时推音乐和当前动作。动作库或基本功把「可以开始」交上来之后，在还没进训练台时，按音乐按钮也会走进练习。全新的一次播放把 AIST 或基本功动作拨回循环起点，和拍子对齐；视频动作没有这一下，它按自己的时间戳走。

睡眠时训练会暂停，相机关掉，「一起跳」离开房间。正常退出会先停相机、等录像文件收尾、等视频和音乐导入、等动作模型写完，再结束。界面上会盖一层「正在保存录像与视频库…」。强制退出不走这条。

![并排训练台](images/live-09-training.png)

*训练台把侧栏让开之后的样子：左示范、右摄像头、底栏仍是音乐。阶段、剩余时间和来源都写在顶上。*

动作画面分几条渲染路径，不要混成一种「舞蹈模型」：

- `AISTAvatarRenderer` / `AISTStageRenderer`：17 个三维关节驱动的柔光或霓虹人形。表面是显示用的，缺关键点的部位隐藏，不插帧。
- `AISTSkeletonView`：同一套关节的经典骨架，左绿右紫。
- `PracticeMotion`：基本功用的生成站立序列，存在 `PracticeMotions/`，打开卡片时准备。
- `CapturedMotion` 和 `AISTSkeleton` 那条二维路径：视频或相机认出来的点，没有深度。叠加时也不假装它是三维。

## 数据模型，以及一次练习怎么被记下来

核心类型都在 `HidanCore`，界面只是把它们驱动起来。

**基本功。** `DanceMove` 是一张卡：中文名、英文名、风格、等级、要点、常见问题、BPM 范围、冲击（低或中等）、是否适合站着练。`DanceCatalog.moves` 里正好 16 张。`DanceStyle` 只有 Hip-Hop、Popping、Locking、House 四个，给文字卡和训练计划用。AIST 自己的 10 个舞种是序列上的 `genreCode`，两套名字不要对死。

**计划。** `TrainingPlan` 是一组 `TrainingBlock`：热身、动作练习、休息、自由组合、放松。时长在 10–45 分钟时，`PlanBuilder` 按风格和等级从文字卡里排；有 AIST 示范时改走 `AISTTrainingPlanBuilder`，四个风格各 3 个名字来自 `Resources/AIST/training-moves.json`，名字本身来自官方元数据。单段跟练用 `AISTPracticePlanBuilder`，组数只允许 2、4、6。编排跟练在 `TrainingStore.prepareArrangement` 里现排：热身 60 秒、每段 60 秒、休息 20 秒、放松 30 秒。

**钟。** `TrainingClock` 是一个值类型。界面每 0.2 秒推一次。只有状态是 `running` 的时间算 `activeSeconds`，休息算在里面，暂停不算，跳过的段落不算完成。一段要把它自己的剩余时间走完，才记进 `completedBlocks`。状态是 `idle / running / paused / completed / stopped`。完成或停掉的钟不能被 `start` 偷着重新开始，要换一份新钟。

**记一笔。** 训练进入完成或停止时，`TrainingStore` 追加一条 `FinishedSession`：日期、计划名、实际秒数、完成段落、总段落、用力感 1–10（没有就空着）。写到 `history.json`。写坏了会把错误留在界面上，可以重试，不用一份损坏文件盖掉好的。视频模型那条跟练的播放进度不进这份历史。

**三维片段。** `AISTSequence` 来自清单：60 FPS、帧数、原始和优化两条相对路径。`AISTMotion` 按 `frame, joint, xyz` 的 Float64 小端读取，每帧 17×3。`AISTPracticeReference` 是拿去练的那一刀：哪条序列、A–B、坐标层、速度、名字。编排 `AISTArrangement` 是这些引用排成的列表，另存在 `Arrangements/`。

**二维动作。** `CapturedMotion` 保留分析报告的全部帧、置信度、人数、原始 PTS。分段是上面的索引，改 A–B 不删原始帧。发布到动作库时再复制一份，新的 UUID，不改视频库里那份分析结果。JSON 导入走 `CapturedMotionImport`：坐标、置信度、帧序、原始 PTS 不一致就按帧号拒绝；只有派生字段（覆盖率、时长、整数 PTS）可以重算，而且每次重算都写进提示。

**音乐。** `TempoMode` 分原创节拍和导入曲。`BeatMultiplier` 是 ¼、½、1、2。`TempoEstimator` 看频谱通量，给一个整体 BPM 和置信度，不找第一拍，最多分析开头 4 分钟。音乐模式下动作速度是「曲目 BPM × 播放速度 × 倍数」，夹在 0.25 和 2 之间，到不了会在训练台上说明。

**一起跳。** 线上的消息在 `PartyProtocol`：问候、欢迎或拒绝、乒乓、共享开关、关节、节拍、倒数、离开，以及 H.264 包。时钟对齐是一组 NTP 式采样。房间码 4 位，用来派生 TLS 预共享密钥。这些不落成媒体文件。`UserDefaults` 只记显示名、随机的对端 ID 和画质。

## 文件放在哪

都在 `~/Library/Application Support/HidanClub/`，除非下面的环境变量把它指走。隔离变量是给探针用的，平时不用设。

| 目录 | 里面是什么 | 环境变量 |
| --- | --- | --- |
| `history.json` 所在目录 | 练习录 | `HIDAN_DATA_DIR` |
| `Videos/` | 原视频和条目 | `HIDAN_VIDEO_DIR` |
| `CapturedMotions/` | 完整二维识别，还在编辑的那份 | `HIDAN_CAPTURE_DIR` |
| `VideoMotionLibrary/` | 导入动作库的独立副本，含 JSON 导入 | `HIDAN_PUBLISHED_DIR` |
| `Arrangements/` | 三维编排和草稿 | `HIDAN_ARRANGEMENT_DIR` |
| `Music/` | 导入音乐的原字节、估计 BPM、手动 BPM、原创节拍预设 | `HIDAN_MUSIC_DIR` |
| `PracticeMotions/` | 基本功生成序列的缓存 | `HIDAN_PRACTICE_MOTION_DIR` |
| `PendingRecordings/` | 录像原件，视频库复制入库之后才算数 | 无，固定在支持目录下 |
| `Datasets/AISTPlusPlus/` | AIST++ 清单和 Float64。不进 Git，不进 `.app` | `HIDAN_AIST_DIR`，或设置里记的 `aist.datasetDirectory` |

损坏记录保留，不静默覆盖。指向库外的符号链接不接受。

AIST 安装：

```bash
python3 script/aist_dataset.py
python3 script/aist_dataset.py --verify-only
```

本机核对过的规模是 1,408 条序列、1,123,873 个独立时间帧、10 个舞种，原始和官方优化都按 Float64 留着，60 FPS，缺测值留在原地。官网那个 10,108,015 是多机位图像，不是独立三维帧。原视频和音乐不在这只 ZIP 里，条款也分开。细节、分舞种张数和署名见 [AIST_DATASET.md](AIST_DATASET.md)。

## 怎么构建，怎么校验

日常只要：

```bash
./script/build_and_run.sh
./script/build_and_run.sh --build
./script/test.sh
```

`build_and_run.sh` 还会在标志 PNG 比 icns 新的时候跑 `script/generate_app_icon.sh`，然后 `swift build`，把二进制和资源收成 `dist/HidanClub.app`，写 `Info.plist`，再 `codesign --sign -`。其它模式：`--verify` 打开并做严格签名检查，`--debug` 进 lldb，`--logs` / `--telemetry` 跟着系统日志看。

`test.sh` 用 `swiftc` 编一个只依赖 Foundation 的核心探针。姿态解码探针要 macOS 14 和 Vision，别的系统会跳过并写明原因。本机有 XCTest 模块时接着跑 `swift test`；没有就说明 Command Line Tools 缺 XCTest，探针通过不等于单元测试已跑。探针失败不会被吞掉。

下面这些是原来 README 里的校验入口，按主题留在这里。都在仓库根目录执行。

```bash
./script/test_media.sh
./script/qa_store.sh
# 安装 AIST++ 数据后：
./script/test_aist.sh
./script/qa_aist_store.sh
./script/qa_aist_appearance.sh
./script/qa_training_stage.sh
./script/qa_training_overlay.sh
./script/test_live_pose.sh
./script/test_camera_recording.sh
./script/qa_video_library.sh
./script/qa_pose_arrangement.sh
./script/qa_video_motion_library.sh
./script/qa_music_library.sh
./script/qa_library_import.sh        # 需要一份真实导出的动作模型 JSON
./script/qa_library_import_ui.sh     # 同上，另存离屏渲染 PNG 到 output/qa-library-import
./script/qa_party.sh                 # 「一起跳」回环连线：TLS-PSK 握手、H.264 往返、节拍同步
./script/qa_party_ui.sh              # 「一起跳」页面离屏渲染 PNG 到 output/qa-party
```

`output/` 不进 Git。离屏渲染能核对视图上的字和结构，不能代替真窗口。这次 README 里的图是真窗口截的。

各轮跑过什么、没声称什么，以 [VERIFICATION.md](VERIFICATION.md) 为准。那里的日期早于后来的界面调整：例如 2026-09-22 还写过编排库里的二维列表，随后的提交把那个列表拿掉了。以现在的 `SequenceView` 为准，编排库只排三维片段。

## 界面和代码对不上的地方

写在这里，免得以后对着旧笔记找按钮。

- 编排库页面没有「导入编排 JSON」。导入按钮只在动作库，目标是「我的动作」。`CapturedLibraryStore.Destination.arrangements` 和 `LibraryImportButton` 的编排文案还在，没有视图引用它们。
- 基本功的四段连播直接播动作，不进编排库。编排库那句说明也是这么写的。
- 动作库列表自动播放用原始坐标；点开和练习用设置里的坐标层。两套文件缺一不可。
- 设置页的默认画面和组数，只在「从动作、编排或视频开始练习」时用。训练台里不再放一套重复的选择器。

## 推断里还没收口的

和 README 同一份判断，这里只标代码位置，方便以后改的时候知道从哪看。不是排期。

- 平台：`Package.swift` 只有 `.macOS(.v14)`。产品说明里的 iPhone / iPad 没有 target。
- 节拍：`TempoEstimator` 拒绝过短和没有稳定周期的音频，注释和错误文案都写明没有第一拍。
- 评分和命名：`DanceCatalog.contentNotice`、训练台的角度反馈、视频分段都把自己限定在观察。`PRODUCT_AND_TECHNICAL_PLAN.md` 把舞步分类、三维估计和自由生成标成后续。
- 历史：`FinishedSession` 只在钟完成或停止时写。视频跟练进度的缺口写在 `TRAINING_STUDIO.md`。
- 一起跳：`PartyService` 按一位对端做。没有中继和多人房间的类型。
- 删除副本：导入路径会新建 UUID，库视图没有对应的删除动作。
